# CCPP linkage adjudication

This directory holds the versioned, disclosure-reviewed identifier crosswalks
needed to reproduce non-exact community linkages. It must contain identifiers
and linkage evidence only—never victimization values, treatment outcomes,
person- or household-level data, testimony, or restricted administrative
content.

## Files

- `ruv-ubigeo-adjudication.csv` maps a public RUV community identifier to an
  adjudicated ten-digit CCPP UBIGEO.
- `cman-ruv-adjudication.csv` maps a CMAN PDF record number to one RUV
  community identifier.
- `ruv-ubigeo-review-decisions.csv` records ambiguous and rejected candidates
  so that they are not silently reconsidered as accepted links.
- `cman-historical-conflict-decisions.csv` records historical CMAN codes
  quarantined because they contradict a direct or verified RUV link.
- `historical-ccpp-source-checksums.csv` fingerprints every newly supplied
  workbook, ReporteCCPP download, and GeoGPS shapefile component.
- `foundational-sample-flow.csv` records aggregate retention and exclusion
  counts generated by the authoritative preparation program.

The authoritative Stata preparation program must validate every row before
applying it. At minimum:

- source keys must be unique;
- CCPP codes must contain exactly ten digits;
- a 2017 code must exist in the authoritative INEI spine, while a later code
  must cite the official administrative source and its actual vintage;
- its six-digit prefix must equal the RUV district code;
- referenced RUV and CMAN records must exist;
- two accepted rows may not produce an unintended many-to-one link; and
- `review_status` must equal `accepted`.

Candidate scores alone are not admissible evidence. `evidence_source` and
`evidence_locator` must identify the official or corroborating source used for
the row-level decision. Historical codes must be labeled with their actual
vintage and must not be presented as current 2017 codes.

The automatic historical pass is intentionally narrower than fuzzy matching.
It accepts an RUV or CMAN code only when the normalized name matches exactly
within the resolved district, every occurrence identifies one ten-digit code,
and—when linking RUV—the code is not already assigned to another retained RUV
record. ReporteCCPP and the GeoGPS DBF represent the same INEI spine and count
as one source family for corroboration.

Exact verified UBIGEO matches take priority in the CMAN-to-RUV merge. A CMAN
record already linked to RUV by reviewed name evidence may inherit that RUV
record's verified UBIGEO. CMAN-only records remain documented in aggregate but
never enter the RUV analysis registry. The RUV source defines the observation
universe: records without a verified CCPP UBIGEO remain in the analysis
registry, are flagged through `ubigeo_ccpp_verified`, and are documented in the
Dropbox Working unresolved-linkage ledger.
