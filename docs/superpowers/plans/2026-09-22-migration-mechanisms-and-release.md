# Migration Mechanisms and Release Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement and validate the migration/mechanism synthesis, publication-candidate inventory, and release audit defined by the approved protocol.

**Architecture:** Reuse the aggregate estimates and manifests already produced by module 04 instead of re-estimating identical RD models. Add one compact versioned analysis registry, one module-06 orchestrator for synthesis plus the only new descriptive association models, one module-07 inventory builder, and one module-08 release auditor. Keep all generated artifacts canonical in Git, marked `generated_unreviewed`, and outside Dropbox and Overleaf.

**Tech Stack:** Stata 19, `rdrobust` results already generated by module 04, local-linear descriptive regressions, CSV/LaTeX/PNG outputs, Stata `checksum`, Stata MCP `stata_run_selection`, Git, Graphify.

**Spec:** `docs/MIGRATION_MECHANISM_PROTOCOL.md`

## Global Constraints

- Run every Stata command through `stata_run_selection`; never use a shell or `stata_run_file` to execute Stata.
- Do not modify Dropbox Raw, Working, Coded, or archived files in this workflow.
- Do not create or write any dataset under Git.
- Use the adjacent B/C sample, `running_bc`, `treat_12`, `treat_16`, common `h=0.0075`, bias `b=0.0135`, triangular kernel, and first-stage gate `F>10` exactly as fixed in the approved protocols.
- CCPP models use district clustering; household and person models retain CCPP-equal weights and CCPP clustering from their source estimates.
- No ACME, ADE, NIE, NDE, proportion-mediated, or product-of-coefficients estimate may be generated.
- Every new table and figure must be aggregate, disclosure-safe, professionally formatted, manifest-listed, and marked `generated_unreviewed`.
- Module 07 must not duplicate canonical artifacts or copy anything to Overleaf.
- Module 08 may return an analytical status of `BLOCKED` without a Stata error when review is the only blocker; missing files, checksum mismatches, unsafe paths, or schema failures remain hard errors.
- Do not stage, commit, or push. Prepare `build/COMMIT_MESSAGE.txt` for user review at the end.

## Review Focus

- **Stale upstream outputs:** changing a module-04 artifact without updating its checksum must make module 07 fail. Covered by Task 3's runtime checksum gate and inventory assertion.
- **Registry drift:** adding a duplicate or invalid evidence class must make the registry test fail. Covered by Task 1.
- **Weak first stage:** a fuzzy estimate with missing or `F<=10` must never be marked reportable. Covered by Task 2's output test.
- **Selection mislabeling:** non-linkage endpoint outcomes must remain `selection_sensitivity`, never observed migration or a causal bound. Covered by Task 2.
- **False release readiness:** unreviewed artifacts must yield `BLOCKED`, while an unsafe path or checksum mismatch must yield a hard failure. Covered by Tasks 3 and 4.
